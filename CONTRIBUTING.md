# Contributing

## Contribution Rules

Contributions must preserve the repository's proof surface and claim boundaries.

Before opening a pull request:

1. Keep changes scoped to one logical unit.
2. Run the relevant verification command from `REPRODUCIBILITY.md`.
3. Do not broaden commercial, benchmark, runtime, or release-readiness claims without committed proof artifacts.
4. Do not remove failing or adverse proof records to improve the narrative surface.
5. Keep source-available license boundaries intact.

## Pull Requests

Open a pull request against the active branch. Do not self-merge. Include:

1. What changed.
2. Verification commands and outcomes.
3. Any proof anchors added, removed, or corrected.
4. Any remaining blocker or kill condition.
